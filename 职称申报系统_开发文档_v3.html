第一章 · CHAPTER 1

系统定位与核心价值

明确系统解决的核心痛点，建立正确的产品方向认知

1.1 背景与痛点

职称申报是工程技术人员职业发展的重要环节。每次申报涉及大量纸质材料收集、表格填写、扫描上传，代办机构面临以下典型问题：

  • 重复录入数据：同一申报人每年申报都要重新填写基本信息
  • 材料遗漏：清单管理依赖Excel，无法实时感知材料上传状态
  • 进度追踪困难：客户材料分散在邮件、微信、U盘，无统一入口
  • OCR质量参差不齐：识别后需要大量人工逐字核对
  • 网报填写耗时：每个申报人手工填写网报系统需要45分钟以上

1.2 核心原则

核心原则：减少录入，不是换个地方录入 系统的价值在于让申报人只填一次数据，后续申报、补充材料、历史复用均自动完成。任何需要操作员重复输入已有信息的设计，都是错误的设计。

1.3 方向对比：错误 vs 正确

❌ 错误方向

  • 每次申报重新录入基本信息
  • 社保、学历信息反复让申报人提供
  • OCR识别后手动逐字核对所有字段
  • 材料清单用Excel发送，无状态追踪
  • 网报系统手动逐项填写，无留存记录
  • 历史申报数据无法复用，每次从零开始

✓ 正确方向

  • 申报人信息一次建档，永久复用
  • 历史材料自动检测是否仍有效（如证书未过期）
  • OCR结果结构化存储，增量更新差异项
  • 清单系统内实时追踪，可见上传进度百分比
  • 自动填报留存截图，全程可审计
  • 二次申报复用率超过70%的历史数据

1.4 工作量削减估算

以下数据基于典型申报案例估算，实际效果因业务复杂度有所差异：

工作内容 传统方式 系统方式 削减比例
基本信息录入 每次手工填写，约 20 分钟 自动带入历史数据，确认约 1 分钟 ~95%
学历 / 培训信息整理 每次重新整理，约 15 分钟 历史复用，仅补充当年新增 ~80%
社保缴纳核实 对账单人工比对，约 30 分钟 自动解析对账单，结构化存储 ~90%
业绩 / 项目材料整理 查找旧材料，约 60 分钟 历史累积，勾选复用即可 ~50%
网报表单填写 手动逐项填写，约 45 分钟 自动填写，人工确认截图 ~85%
合计（首次建档后） 约 170 分钟 / 人次 约 30 分钟 / 人次 ~75%
注意 首次建档时仍需完整录入申报人信息（约60分钟）。削减效果从第二次申报开始显现，且数据积累越多，后续效率提升越明显。
第二章 · CHAPTER 2

核心流程（10阶段工作流）

从政策解析到提交后跟踪的完整业务闭环

系统将每次职称申报拆解为11个标准阶段（阶段0～10），各阶段有明确的输入、输出和负责角色。

0

政策解析与清单生成

从官方发布文件中提取职称类别、申报条件、材料要求、分值计算规则，生成本批次标准材料清单模板。支持人工录入和文档OCR两种方式。

1

新建申报人 + 生成个性化清单

建立或更新申报人档案（历史申报数据自动带入）。根据申报职称类别、学历、现职称等条件，从模板清单中生成个人差异化材料清单。

2

本地目录创建

在指定路径自动创建标准化文件夹结构，按材料类型分类。
示例路径：D:/申报材料/2026年批次/张三_高级工程师/01_身份证/

3

清单发送客户

生成带状态的材料清单（PDF格式或在线链接），明确标注每项材料的具体格式要求（分辨率、页数、颜色）和截止日期。支持微信/邮件发送。

4

材料收集追踪（Watchdog 文件监听）

对申报人文件夹启动文件系统监听（watchdog库），自动检测新上传/修改的文件。实时更新材料状态：未收 → 已收待核 → 已核验。触发进度通知。

5

材料预检

自动检查：文件格式（PDF/JPG/PNG）、图像分辨率（≥300dpi）、文件大小（<20MB）、页数是否完整。输出预检报告，标注不合格项，通知客户重新提供。

6

OCR识别 + 人工复核

对收到的材料执行OCR识别，提取结构化字段并写入数据库。人工复核界面高亮显示低置信度字段和与历史数据冲突的项目，操作员确认后更新申报人档案。

7

资格预审

根据职称申报规则引擎，检查：工作年限、学历要求、现职称持有年限、继续教育学时、业绩分值是否达标。输出预审报告，标注风险点和差距项，供操作员与客户沟通。

8

准备填报数据

汇总所有字段，生成网报系统所需的结构化数据集。人工最终确认：逐字段预览，标记不确定项，冻结数据版本（此后修改需记录变更原因）。

9

自动填报

使用 Playwright 驱动浏览器，自动登录网报系统，逐字段填写申报表单。每个页面截图存档，填写过程可回放。遇到验证码或异常情况自动暂停，等待人工介入。

10

提交后跟踪

记录受理号、初审/复审状态、公示时间、证书发放时间。定期（可配置）自动检查网报系统状态变化，触发微信/短信通知。结果存入contact_logs，支持历史查询。

第三章 · CHAPTER 3

数据模型

系统核心数据表结构设计，覆盖申报人全生命周期数据

3.1 申报人主表 applicants

存储申报人的完整档案信息，一人一档，跨批次复用。所有关联表均通过 applicant_id 外键引用。

CREATE TABLE applicants (
    -- 主键与时间戳
    id               INTEGER PRIMARY KEY AUTOINCREMENT,
    created_at       DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at       DATETIME DEFAULT CURRENT_TIMESTAMP,

    -- 基本信息
    name             TEXT NOT NULL,          -- 姓名
    id_card          TEXT UNIQUE,            -- 身份证号（加密存储）
    gender           TEXT,                   -- 性别：男/女
    birth_date       TEXT,                   -- 出生日期 YYYY-MM-DD
    ethnicity        TEXT,                   -- 民族
    political_status TEXT,                   -- 政治面貌
    phone            TEXT,                   -- 手机号
    email            TEXT,                   -- 邮箱
    native_place     TEXT,                   -- 籍贯（省市）

    -- 单位信息
    company          TEXT,                   -- 工作单位全称
    department       TEXT,                   -- 所在部门
    position         TEXT,                   -- 担任职务/岗位名称
    employment_type  TEXT,                   -- 用工类型：正式/劳务/其他
    work_start_date  TEXT,                   -- 参加工作时间 YYYY-MM

    -- 学历信息（最高学历）
    highest_edu      TEXT,                   -- 学历层次：大专/本科/硕士/博士
    highest_school   TEXT,                   -- 毕业院校
    highest_major    TEXT,                   -- 所学专业
    graduation_year  TEXT,                   -- 毕业年份 YYYY

    -- 现职称信息
    current_title    TEXT,                   -- 现有职称名称
    title_level      TEXT,                   -- 职称级别：初级/中级/高级
    title_cert_no    TEXT,                   -- 职称证书编号
    title_date       TEXT,                   -- 获得职称时间 YYYY-MM
    title_unit       TEXT,                   -- 评定单位

    -- 本次申报信息
    target_title     TEXT,                   -- 申报职称名称
    target_level     TEXT,                   -- 申报级别
    specialty_field  TEXT,                   -- 申报专业领域

    -- 状态与备注
    status           TEXT DEFAULT 'active',  -- active/inactive/archived
    notes            TEXT                    -- 备注信息
);

3.2 工作经历表 work_experiences

记录申报人完整工作履历，支持多段经历，自动生成年限统计。

CREATE TABLE work_experiences (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    applicant_id INTEGER NOT NULL REFERENCES applicants(id) ON DELETE CASCADE,
    start_date   TEXT NOT NULL,              -- 开始时间 YYYY-MM
    end_date     TEXT,                       -- 结束时间（NULL或"至今"表示当前）
    company      TEXT NOT NULL,              -- 单位名称
    position     TEXT,                       -- 职务/岗位
    is_current   INTEGER DEFAULT 0,          -- 是否当前单位 0/1
    notes        TEXT                        -- 备注
);

3.3 社保记录表 social_insurance

逐月存储社保缴纳记录，由对账单OCR自动解析写入，支持连续性验证。

CREATE TABLE social_insurance (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    applicant_id    INTEGER NOT NULL REFERENCES applicants(id) ON DELETE CASCADE,
    year_month      TEXT NOT NULL,           -- 年月 YYYY-MM
    insured_company TEXT,                    -- 参保单位名称
    insurance_type  TEXT,                    -- 险种：养老/医疗/工伤/失业/生育
    amount          REAL,                    -- 缴费金额（元）
    source_file     TEXT,                    -- 来源文件路径
    parsed_at       DATETIME,               -- 解析时间
    verified        INTEGER DEFAULT 0        -- 人工核验标志
);

3.4 业绩成果表 achievements（扩展版）

统一存储项目、奖项、论文、标准、专利等各类业绩，type字段区分类型，支持分值计算。

CREATE TABLE achievements (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    applicant_id INTEGER NOT NULL REFERENCES applicants(id) ON DELETE CASCADE,
    type         TEXT NOT NULL,              -- project/award/paper/standard/patent
    title        TEXT NOT NULL,              -- 成果名称/项目名称
    role         TEXT,                       -- 本人角色/排名
    year         TEXT,                       -- 年份 YYYY
    org          TEXT,                       -- 颁发/发布机构
    level        TEXT,                       -- 级别：国家级/省级/市级/区级
    score        REAL,                       -- 系统按规则计算的分值
    cert_file    TEXT,                       -- 证书/证明文件路径
    verified     INTEGER DEFAULT 0,          -- 是否已人工核验
    batch_ids    TEXT,                       -- 关联批次ID列表（JSON数组）
    notes        TEXT
);

3.5 继续教育/培训表 edu_trainings

记录年度继续教育和专业培训，自动汇总年度学时，校验是否满足申报要求。

CREATE TABLE edu_trainings (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    applicant_id INTEGER NOT NULL REFERENCES applicants(id) ON DELETE CASCADE,
    year         TEXT NOT NULL,              -- 年份 YYYY
    course_name  TEXT NOT NULL,              -- 课程/培训名称
    hours        REAL,                       -- 学时数
    org          TEXT,                       -- 培训机构名称
    cert_no      TEXT,                       -- 证书编号
    cert_file    TEXT,                       -- 证书文件路径
    notes        TEXT
);

3.6 职业资格证书表 pro_certificates

存储注册工程师、建造师等执业资格证书，自动检测有效期预警。

CREATE TABLE pro_certificates (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    applicant_id INTEGER NOT NULL REFERENCES applicants(id) ON DELETE CASCADE,
    cert_name    TEXT NOT NULL,              -- 证书名称（如：二级建造师）
    cert_no      TEXT,                       -- 证书编号
    issued_by    TEXT,                       -- 颁发机构
    issued_date  TEXT,                       -- 颁发日期 YYYY-MM-DD
    valid_until  TEXT,                       -- 有效期至 YYYY-MM-DD（NULL表示长期有效）
    cert_file    TEXT,                       -- 扫描件文件路径
    notes        TEXT
);

3.7 材料文件表 materials

追踪每个申报人每次批次的所有材料收集状态，是流程管控的核心表。

CREATE TABLE materials (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    applicant_id  INTEGER NOT NULL REFERENCES applicants(id),
    batch_id      INTEGER NOT NULL REFERENCES batches(id),
    material_type TEXT NOT NULL,             -- 材料类型代码（见第四章映射）
    material_name TEXT NOT NULL,             -- 材料显示名称
    required      INTEGER DEFAULT 1,         -- 是否必须 0/1
    file_path     TEXT,                      -- 文件存储路径
    file_size     INTEGER,                   -- 文件大小（bytes）
    page_count    INTEGER,                   -- 页数
    status        TEXT DEFAULT 'pending',    -- pending/received/checking/verified/rejected
    ocr_done      INTEGER DEFAULT 0,         -- 是否已完成OCR
    ocr_result    TEXT,                      -- OCR提取结果（JSON格式）
    check_result  TEXT,                      -- 预检结果（JSON格式）
    reject_reason TEXT,                      -- 驳回原因
    uploaded_at   DATETIME,                  -- 上传/接收时间
    verified_at   DATETIME,                  -- 核验完成时间
    notes         TEXT
);

3.8 其他业务支撑表

-- 项目详情表（与achievements关联，存储工程项目具体信息）
CREATE TABLE projects (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,

    achievement_id INTEGER REFERENCES achievements(id),
    project_name TEXT NOT NULL,              -- 项目名称

    scale        TEXT,                       -- 建设规模描述

    area         REAL,                       -- 建筑面积（平方米）
    location     TEXT,                       -- 项目地点

CREATE TABLE awards (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    applicant_id INTEGER REFERENCES applicants(id),
    award_name   TEXT NOT NULL,              -- 奖项名称
    award_level  TEXT,                       -- 奖励等级（一等奖/二等奖等）
    rank         TEXT,                       -- 本人排名/角色
    issued_by    TEXT,                       -- 颁奖机构
    year         TEXT,                       -- 获奖年份
    cert_file    TEXT                        -- 获奖证书文件路径

CREATE TABLE papers (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,

CREATE TABLE fees (

    fee_type     TEXT,                       -- 费用类型（代办费/评审费/材料费）
    amount       REAL NOT NULL,              -- 金额（元）
    paid_at      DATETIME,                   -- 缴费时间
    receipt_no   TEXT,                       -- 收据编号
    payment_method TEXT,                     -- 支付方式
    notes        TEXT
);

-- 联系沟通记录表
CREATE TABLE contact_logs (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    applicant_id INTEGER REFERENCES applicants(id),
    log_time     DATETIME DEFAULT CURRENT_TIMESTAMP,
    channel      TEXT,                       -- 沟通渠道：微信/电话/邮件/面谈
    direction    TEXT,                       -- 方向：outbound/inbound
    content      TEXT,                       -- 沟通内容摘要
    operator     TEXT,                       -- 操作员
    next_action  TEXT                        -- 待跟进事项
);
第四章 · CHAPTER 4

材料字段映射规范

定义10类核心材料的OCR提取字段、写入目标及识别方式

本章为OCR模块的核心配置文档。每类材料定义：提取字段（从文件中识别的信息）、写入目标（存入哪张表的哪些字段）、识别方式（技术实现方法）。

置信度阈值约定 OCR置信度 ≥ 0.92：自动写入数据库；0.75～0.92：写入并标记待确认；< 0.75：写入原始文本，要求人工录入。
① 居民身份证 OCR + 正则匹配
姓名 性别 民族 出生日期 身份证号码 户籍地址 签发机关 有效期限
识别方式：标准正面/背面模板匹配，身份证号用18位正则校验，出生日期从证号第7-14位提取并交叉核验
写入目标：applicants.name / id_card / gender / birth_date / ethnicity / native_place
② 学历 / 学位证书 OCR + 关键词定位
证书持有人姓名 毕业院校名称 所学专业 学历层次 学位类型 毕业年月 证书编号
识别方式：以"学历证书"/"毕业证书"/"学位证书"关键词定位文档类型，按字段区域坐标提取，学历层次做枚举归一化处理
写入目标：applicants.highest_edu / highest_school / highest_major / graduation_year；同步检查是否覆盖现有记录
③ 现职称证书 OCR + 模板匹配
持证人姓名 职称名称 职称级别 专业类别 证书编号 评定机构 评定时间
识别方式：职称证书格式因省市而异，使用多套区域模板匹配，优先提取红头文件顶部机构名和证书编号区域
写入目标：applicants.current_title / title_level / title_cert_no / title_date / title_unit
④ 社保缴费证明 / 对账单 OCR + 表格结构解析
参保人姓名 身份证号 参保单位 险种名称 缴费年月（逐行） 缴费金额（逐行） 缴费状态
识别方式：使用表格线检测算法提取行列结构，逐行解析年月和金额，支持PDF文字层直接提取（优先），图像OCR为备选。自动识别连续缴纳月数
写入目标：social_insurance表（逐月逐险种插入），重复记录更新而非新增
⑤ 职业资格证书 OCR + 正则匹配
证书名称 证书编号 持证人姓名 颁发机构 颁发日期 有效期限 注册专业

接口功能识别内容
POST /ocr/id-card身份证识别姓名/身份证号/性别/出生日期/民族/地址（正面）；有效期（背面）

@bp.route("/generate", methods=["POST"])
def generate():
    data = request.json or {}
    doc_type = data.get("doc_type", "work_summary")
    fields   = data.get("info") or data.get("fields") or {}

    def stream():
        from core.ai_writer import stream_write
        for chunk in stream_write(doc_type, fields):
            yield f"data: {json.dumps({'text': chunk}, ensure_ascii=False)}\n\n"
        yield "data: [DONE]\n\n"

    return Response(stream(), mimetype="text/event-stream",
                    headers={"X-Accel-Buffering": "no", "Cache-Control": "no-cache"})

第十章

密码加密与安全

Fernet 对称加密保护敏感凭证

申报人在 gxrczc.com 的登录密码、各平台 API Key 均属于敏感信息，不能明文存入 SQLite。系统使用 cryptography 库的 Fernet 对称加密方案。

安全原则：密钥文件与数据库文件分开存放。即使数据库被复制走，没有密钥文件也无法解密。 如需迁移，必须同时复制密钥文件。 
# core/crypto.py
from cryptography.fernet import Fernet
from config import KEY_PATH

def _load_or_create_key() -> bytes:
    if KEY_PATH.exists():
        return KEY_PATH.read_bytes()
    key = Fernet.generate_key()
    KEY_PATH.parent.mkdir(parents=True, exist_ok=True)
    KEY_PATH.write_bytes(key)
    return key

def encrypt(plain_text: str) -> str:
    return Fernet(_load_or_create_key()).encrypt(plain_text.encode()).decode()

def decrypt(cipher_text: str) -> str:
    try:
        return Fernet(_load_or_create_key()).decrypt(cipher_text.encode()).decode()
    except Exception:
        return ""
场景操作
保存密码/API Key调用 encrypt()，将密文存入数据库或 config.json
启动自动填报前调用 decrypt() 取出明文，传给 Playwright
界面展示密码框始终显示 ••••••，不在任何位置显示明文
